N-VAN e: の OBD を自作の道具で読みました

何をしたECU 01 に UDS 22 の読み出し要求を送り、駆動用バッテリーの値を応答から読みました。
どうつないだMX+（SPP）か CX（BLE）→ ESP32 → 家の Wi-Fi。中継とソフトは自作です。
何が読めた確定 17・ほぼ確定 4・候補 6。容量・SOC・電流・電圧・セル・12V など。
別の車でもECU の地図 → DID の総当たり → 予想値と突き合わせ → 操作で確認、の 4 段は同じです。
次12V バッテリーの状態・シフトの位置・エアコンの入り切りの印の在りかを探します。

1読めた値

ECU 01（駆動用バッテリー）の 22 202A は 246 バイトの応答で、主な値はここにあります（位置＝応答の先頭 0x62 を 0 とするバイト位置・big endian）。

2車の状態と OBD の応答

ECU が応答するのは「ON」「READY」「充電中・電源 ON」の時だけです。IG OFF の充電中は NO DATA で、読めるのはアダプタの端子の 12V（ATRV）だけです。

3CX と ESP32-S3 で、走行中も自動で記録

  • BLE：サービス FFF0。FFF1 の通知で応答を受け、FFF2 への書き込みで要求します。組めるのは CX の電源が入ってから 5 分の間です（公式）。
  • MX+ と同じ値：202A の長さは 246 バイトで同じ。2035 の電圧 ÷（96×セルの最高と最低の平均）＝1.0002で、MX+ の時と同じでした。
  • 走行中：車速の応答率 99.9%・12V（ATRV）12.9〜14.5V。記録は ESP32-S3 の PSRAM と flash の区画に貯め、家の Wi-Fi で NAS が引き取ります。
  • スリープ：STSLEEP で眠った CX が、12V の変化（VCHG）で起きた記録があります。

4調べ方（この車で 4 段）

  1. ECU の住所の地図を作る：18DAxxF1 の xx を回し、22F187 に応答した ECU を記録
  2. DID を全部要求する（総当たり）：読み出しの要求（UDS 22）を、DID を変えて順に全部送る
  3. 予想値と突き合わせる：諸元の容量・電圧、アプリの表示、アメダス
  4. 操作で 1 つずつ確かめる：エアコン・ライトの ON/OFF で変化したバイトを探す
命令と考え方
  1. 規約：0100 を送り ATDPN で表示。この車は 7（ISO 15765-4 CAN 29bit 500kbps）。11bit の車は住所が 7E0〜7E7 など。
  2. 住所の地図：18DA{xx}F1 の xx を 00〜FF で回し、ATSH18DA{xx}F1・ATCRA18DAF1{xx} の後に 22F187（部品番号）。応答した xx が ECU。機能の住所 18DB33F1 への 0100 に応答したのは 07 だけ。
  3. 総当たり：各 ECU に 22＋番号（2000〜20FF・7000〜70FF）。62 で始まれば肯定、7F 22 31 は requestOutOfRange。長い応答は ISO-TP の複数の枠なので、flow control を ATFCSH・ATFCSD300000・ATFCSM1 で明示。
  4. 突き合わせ：諸元（82.7Ah・358V → 96 直列）、アプリの容量 80.14Ah＝0x1F4E、メーターの外気温。型＝1 バイトで値−40（温度）、2 バイトで ×0.1 か ×0.01、電流は符号付き。
  5. 操作：エアコンやライトを 1 つずつ入れ、前後の応答の差を取って動いたバイトだけを見ます。
  6. 近道：Clarity の公開例と同じ住所・同じ DID（18DA01F1・22 202A）で応答し、位置だけが違いました。

Python の例（TCP 35000 の中継で読む） 
import re, socket

def ask(s, cmd, wait=8.0):
    s.sendall((cmd + "\r").encode())
    s.settimeout(wait)
    buf = b""
    while not buf.rstrip().endswith(b">"):
        buf += s.recv(4096)
    return buf.decode(errors="replace")

def payload(raw):
    """ISO-TP の枠を 1 つの応答に組み直す"""
    fr = [[int(x, 16) for x in re.findall(r"\b[0-9A-F]{2}\b", ln)[4:]]
          for ln in raw.splitlines() if ln.startswith("18 DA")]
    if fr[0][0] >> 4 == 0:
        return fr[0][1:1 + (fr[0][0] & 0x0F)]
    n = ((fr[0][0] & 0x0F) << 8) | fr[0][1]
    data = fr[0][2:]
    for f in fr[1:]:
        data += f[1:]
    return data[:n]

s = socket.create_connection(("<ESP32 の住所>", 35000))
for c in ["ATE0", "ATL0", "ATS1", "ATH1", "ATTP7", "ATSH18DA01F1", "ATCRA18DAF101",
          "ATFCSH18DA01F1", "ATFCSD300000", "ATFCSM1"]:
    ask(s, c)
p = payload(ask(s, "22202A"))
assert p[0] == 0x62
print("駆動用バッテリーの容量", round((p[170] << 8 | p[171]) * 0.01, 2), "Ah")

  • MX+ 用：ESP32（esp32dev）。ESPHome に自作の外部部品（SPP⇔TCP の中継・SSP の Just Works で組む）。
  • CX 用：ESP32-S3（PSRAM 8MB）。ESPHome に自作の外部部品（BLE⇔TCP の中継・自分読みと貯め・web で記録を渡す）。
